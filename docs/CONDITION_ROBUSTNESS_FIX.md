# 観測条件推定の原因分析と修正

## 対象と判断方法

対象は、シミュレーションにおける「遮蔽による10%以上の点数損失」の推定。
転倒検知そのものの性能、実機2D LiDARでの性能、任意の未知環境での保証とは区別する。
既存のしきい値調整が未知条件に移らない原因を切り分け、修正候補を選び、
候補を選ぶのに使わなかったseed・遮蔽物配置で確認した。

## 原因の切り分け

1. **確率計算の丸め・飽和は今回の主因ではない。** 距離差を指数関数に通さない
   安定なスコアに置き換えても、25 foldすべてで固定判定・調整後判定の結果が変わらなかった。
2. **局所点数の基準値が、観測開始時の動きに強く依存する。** 各区画の時間方向の中央値を
   基準としていたが、人が区画を移動するため基準が0になる。50系列中43系列に0の区画があり、
   450区画中189区画が0だった。基準0の場合、後から点が現れても比率は0として扱われていた。
   例として、点数が160程度の系列でも、区画基準の合計が16にしかならなかった。
3. **基準を平均へ置換するだけでは解決しない。** 同じ分割・推定器で平均基準へ変えると
   AUCは0.927から0.511へ落ちた。これは従来の識別結果が基準値の作り方に依存していた証拠であり、
   平均基準を性能改善策として採用する根拠にはならない。平均基準は比較実験用として保存した。
4. **形状特徴を単純な重心分類だけで扱うと識別力が足りない。** 基準に依存しない同じ形状特徴で
   重心分類から二次項を含む正則化回帰へ変えると、開発データで改善した。単にしきい値を変えた結果ではない。
5. **家具条件の学習範囲が狭かった。** 最初の確認実験では広く高さのある家具に性能低下が集中。
   そこで高さ・位置を変えた家具を学習側へ追加し、さらに別の未使用条件で再確認する計画を固定した。

これらは実施した比較からの判断であり、実世界で起こる失敗原因のすべてを特定したという意味ではない。

## 修正した方式

- 局所点数の中央値による正規化を採用候補から外した。
- 観測の有無、zの平均・標準偏差・分位点、床付近の点の比率、x/y方向の広がりの11特徴を使用。
- 過去5 frameの平均のみを使用し、未来frameや別系列のframeは混ぜない。
- 学習データだけから標準化し、二次項・交互作用を含むridge回帰で観測劣化スコアを作る。
  ridge強度1、標準化後のclip幅8は候補選定時に固定。スコアは確率とは表記しない。
- しきい値は別seedの調整用データで、各配置の経験的FPRが5%以下になるように固定する。
- 点数そのもの、設置・遮蔽設定、正解ラベル、clear参照をモデル入力に使わない。

`src/robust_condition.py` に修正候補のスコアモデルを実装した。
testbed側に元からあった未コミット変更は編集していない。

## 開発用25 foldの比較

| 方式（調整時FPR上限5%） | 観測劣化recall平均 | FPR平均 | recall=0のfold数 |
|---|---:|---:|---:|
| 従来の区画基準＋重心分類 | 0.620 | 0.149 | 6 |
| 形状特徴＋重心分類 | 0.642 | 0.046 | 0 |
| 形状特徴＋二次回帰 | 0.965 | 0.036 | 0 |

同じ開発データで候補を比較した結果であり、最終確認値ではない。

## 最初の未使用条件による確認

設定は `57be5cf` で固定。学習seedは0–3、しきい値調整は4、評価seedは101–105。
評価は新しい壁・家具5配置との全25組。基準を満たさなかった結果も保存した。

| 方式 | 観測劣化recall平均 | FPR平均 |
|---|---:|---:|
| 従来・しきい値調整 | 0.422 | 0.094 |
| 従来・固定しきい値 | 0.785 | 0.253 |
| 修正候補 | 0.901 | 0.029 |

平均値は改善したが、幅広い家具のrecall平均が0.680で、配置別基準に不合格。
初回確認後にこの結果を開発上の根拠として使ったため、再確認には101–105を使わない。

## 再確認の事前設定

設定は `4e2790a` で固定。モデル・特徴・しきい値の選び方は維持し、家具の高さ
0.45/0.70/1.15/1.50と2つの位置を組み合わせた8配置を学習・調整側へ追加した。
元の5配置と合わせて13配置。評価seedは201–205、評価配置も新しい5種類へ変更した。

事前の工学的合格基準は両確認実験で同じ。実用上の安全基準ではない。

- 全体の平均recall ≥ 0.90、平均FPR ≤ 0.10。
- 各配置の平均recall ≥ 0.80、平均FPR ≤ 0.10。
- 各seed・配置のrecall ≥ 0.70。

## 再確認結果と到達点

二回目の未使用条件による確認では、事前基準をすべて満たした。
`results/condition_robustness_holdout_v2.json` に全25条件の混同行列としきい値を保存した。

| 方式（同じ学習・調整・評価条件） | 観測劣化recall平均 | FPR平均 |
|---|---:|---:|
| 従来・しきい値調整 | 0.259 | 0.037 |
| 従来・固定しきい値 | 0.815 | 0.311 |
| 修正方式 | **0.943** | **0.024** |

| 新しい配置 | 修正方式のrecall平均 | FPR平均 |
|---|---:|---:|
| 縦壁 | 0.933 | 0.029 |
| 横壁 | 0.972 | 0.013 |
| 低い家具 | 0.926 | 0.022 |
| 幅広い家具 | 0.930 | 0.027 |
| 家具2個 | 0.956 | 0.031 |

全25組の最低recallは0.839、最大FPRは0.054。
**今回事前に定めたシミュレーション上の確認範囲では、未知条件への移植性を改善する目標を達成した。**
この有限の確認範囲を超える一般保証ではない。
初回と二回目は評価条件が異なるため、初回の家具0.680と二回目の家具0.930の差を
同じ評価セットに対する改善量としては扱わない。

## 再現手順

元のtestbedは、前の結果JSONに記録したcommitと
`results/condition_threshold_validation.testbed.patch` から復元できる。
本結果のJSONにもtestbedの正規化SHA-256を保存する。

```powershell
$env:OPENBLAS_NUM_THREADS = '1'
& ./heterosense-fl-testbed/.venv/Scripts/python.exe experiments/condition_failure_diagnosis.py
& ./heterosense-fl-testbed/.venv/Scripts/python.exe experiments/condition_baseline_ablation.py
& ./heterosense-fl-testbed/.venv/Scripts/python.exe experiments/condition_shape_models.py
& ./heterosense-fl-testbed/.venv/Scripts/python.exe experiments/confirm_condition_robustness.py
& ./heterosense-fl-testbed/.venv/Scripts/python.exe experiments/confirm_condition_robustness.py --config configs/condition_robustness_holdout_v2.json
& ./heterosense-fl-testbed/.venv/Scripts/python.exe -m pytest tests -q
```

NumPy特徴キャッシュは `results/local_*.npz` にローカル保存し、Gitへ登録しない。
Gitへ登録するのはコード・固定設定・小さな集計JSON・文書。
Python 3.14.3 / NumPy 2.5.2で検証。testbedの列挙対応Python版外である点は継続する。
frame間・fold間は独立ではなく、平均値を信頼区間や保証として扱わない。

研究本体のテスト13件が成功。区画基準の点数保存、ラベル非依存性、二次項の識別力、
推論時に標準化基準を変更しないこと、しきい値制約、分割、条件別合否判定を確認する。

## 残る適用上の制約

このシミュレータはz座標を含む合成点群と2.5次元の遮蔽モデルを使う。
実機2D LiDARで同じ高さ特徴を取得できるかは別途確認が必要。
点数そのものを外していても、合成形状の生成規則を利用している可能性は残る。
また、完全な情報欠落など、観測だけから区別できない場面全般を解決したわけではない。

P1の転倒しきい値への接続は、固定した転倒スコアとの比較で転倒の見逃し・誤報の改善を
確認した後に行う。この作業の結果を「転倒検知の精度」として報告しない。
