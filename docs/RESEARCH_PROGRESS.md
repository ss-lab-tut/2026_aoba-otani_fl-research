# 研究進捗まとめ

## 1. 研究の現在地

本研究では、施設や設置方法によって異なる観測条件の下で、2D LiDAR等を用いた転倒検知を行います。これまでの結果ではhard negativeを増やすと誤報が減る一方、角部屋でrecallが `0.951 → 0.919` に低下しました。データ補強だけではこのトレードオフを解消できないため、次の研究質問に取り組みます。

> 観測条件（設置ジオメトリ・遮蔽・センサー可用性）を観測統計から推定し、転倒検知をその条件で切り替えることで、データ補強や設置の工夫だけでは解決できなかったトレードオフを改善できるか。

条件推定器には、point count、可視点比率、z分布、baselineとの差分、圧力値の有無など、実運用時に観測できる値だけを入力します。シミュレータ内部の遮蔽・設置パラメータを入力に使いません。

### fall-motion再導入で行ったこと

- 新規の乱数呼び出しを共有RNGではなく `rng.spawn()` 由来の子生成器へ分離
- `fall_motion_diversity=False` を既定値にし、v1既定経路を変更しない構成に修正
- 多様化を有効にした場合だけLiDAR観測用の転倒形状を変更
- 通常行動へ影響していたhard-negative変更を除外
- fall-motion、RNG分離、v1互換性のテストを追加
- 現環境でv1.0.0と既定出力を直接比較し、双方のSHA-256が `7331e92499808964ae015e231dd2160e12604fc5c7f7b9c14651b93de32e53a0` で一致

このSHA-256は現環境での比較結果です。旧NumPy／別プラットフォームで記録されたハッシュとは浮動小数点表現の差で一致しない可能性があるため、構造の完全一致と数値要約の許容誤差比較もテストしています。

### 条件推定の土台として行ったこと

`heterosense/observation_statistics.py` に次の観測統計を実装しました。

- センサーモダリティの可用性フラグ
- 点数と可視点比率
- zの平均、標準偏差、分位点、baselineとの差
- 床付近の点の割合
- x/y/xy方向の広がり
- 圧力値の合計、平均、標準偏差、最大値、active比率、baselineとの差

`ObservationBaseline.fit()` は観測されたcalibration frameだけから基準値を作ります。センサーがない場合は可用性フラグとゼロ値で明示し、隠れたシミュレータパラメータは使いません。

## 3. 比較する実験

| ID | 構成 | 目的 |
|---|---|---|
| B1 | 素のCNN＋共通閾値 | WALL_OCCLUDED held-outの基準再現 |
| B2 | 補強CNN＋共通閾値 | データ補強の基準再現 |
| B3 | 補強CNN＋施設別閾値 | 角部屋対策を含む強い比較対象 |
| B4 | 天井設置＋単純CNN | 設置の工学だけで達成できる範囲を確認 |
| P1 | 条件推定器＋動的閾値 | 推定器だけを学習し、条件に応じて閾値を変更 |
| P2 | 条件出力を追加したCNN | 条件埋め込み、または条件別headを比較 |

主な比較相手はB3とB4です。P1/P2が超えられなかった場合も、その結果をそのまま報告します。

## 4. 評価方法

平均精度は主要指標にしません。次を5 seedで実行し、平均±標準偏差を報告します。

- 条件別のrecall–false alertsトレードオフ曲線
- WALL_OCCLUDED held-out
- LiDARのみ角部屋
- harsh施設
- 遮蔽下の通常行動
- 天井視野端
- 全条件のうち最も悪い条件でのrecall

実験表には設定ファイル、データ分割、seed、commit ID、実行環境、出力ファイルを対応付けます。

## 6. 現在不足しているもの

- B1/B2の `0.291` / `0.987` を生成した元ログ、設定、checkpoint、データ分割
- B3の施設別閾値の実装と評価
- B4の天井設置モデルと、天井固有の視野端疎化・家具直下の影・姿勢識別困難性の妥当なモデル化
- P1の条件ラベル定義、条件推定器の学習、動的閾値の実装
- P2の条件埋め込み／条件別headの実装
- 条件ごとの固定評価セットと5 seed実験runner
- false alertsの単位（frame、event、時間当たり）の確定
- 大容量データの取得方法、前処理、分割、checksumを記したデータマニフェスト
- 対応範囲内の固定環境での再実行

3D LiDARは当面使いません。導入後は、条件推定器が実点群でも遮蔽・設置条件を推定できるか、天井シミュレーションが実点群にどれだけ近いかを最初に検証します。

## 7. 次に行う作業

1. GitHubへ公開済みの3本のfeature branchからPRを作成し、先生のレビューを受ける。
2. 先生に元のB1/B2実験資産の場所を確認し、再現可能なrun manifestへ固定する。
3. false alertsの定義と条件ラベルを確定し、条件別評価datasetを生成する。
4. B1/B2を5 seedで再現し、以降の正式値の基準を作る。
5. B3とB4を実装・評価する。
6. P1を先に実装し、効果が確認できた後にP2へ進む。

毎日の作業終了時に、ブランチ、commit、テスト結果、生成物、次の作業をこの文書またはPRへ追記します。
